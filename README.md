# Mi_Max Ai 3.0 — Android

تطبيق Android أصلي بلغة Java. الحزمة `com.mimax.ai`، الحد الأدنى Android 8 (API 26). إصدار التطوير 3.0.0.
يعمل على ARM32 وARM64 وx86 لأنه Java خالص بلا مكتبات أصلية.

## البناء
- Android Studio: افتح المجلد ثم Build ← Build APK.
- أو `mimax-build.sh` في Termux (يرفع المشروع إلى GitHub ويبني الـAPK).

## الميزات الموجودة في المصدر الأساسي
### صور الرومات (الملفات ← اضغط على ملف .img)
- **اكتشاف النوع من المحتوى** مع الأدلة التقنية والحالة (صالحة / تالفة / مبتورة / غير مدعومة).
- **Sparse ⇄ Raw:** تحويل في الاتجاهين (Raw→Sparse يستخدم FILL للأصفار والأنماط مثل img2simg).
- **super.img:** عرض الأقسام، تحديد واستخراج أقسام، **إعادة تجميع** super بأقسام معدَّلة (مع التحقق بايتاً ببايت)، ونسخة Sparse اختيارية.
- **ext4:** تصفح الملفات، استخراج ملف أو مجلد أو الكل، **تعديل في المكان**: استبدال محتوى ملف نصي (بحجم أقل أو يساوي مساحته المخصصة)، وتغيير الأذونات والمالك. يحدّث مجموع inode عند metadata_csum. التعديل يتم على نسخة `_edited` ولا يُلمس الأصل.
- دورة العمل: فك super ← فتح القسم وتعديل ملف ← إعادة التجميع تلقائياً بالنسخ `_edited`.
### خيارات المطور (مخفية)
تخصيص لون كل عنصر: الخلفية، الأسطح، الحدود، النصوص، التمييز، الخطأ، بقع الزجاج، فقاعات المحادثة، الشريط العلوي والسفلي، ولون الزجاج. مع إعادة ضبط.
### الخطوط
نوع الخط (8 أنواع + خط من ملف ttf/otf) وحجم الخط 70%–200% (الإعدادات ← المظهر).
### تثبيت التطبيقات
تثبيت APK وAPKS وXAPK عبر PackageInstaller الرسمي مع طلب إذن «تثبيت تطبيقات غير معروفة». التأكيد النهائي في نافذة النظام.

## الاختبارات (على JVM / Linux وليس على جهاز Android)
- محرك الصور: **24 اختباراً، 24 نجحت** (`TEST_REPORT_IMG.md`).
- محرك ZIP/cpio/LZ4/boot: **36 اختباراً، 36 نجحت** (`TEST_REPORT.md`).
- صور ext4 أنشأتها mke2fs 1.47 وفُحصت بـ e2fsck بعد كل تعديل. صور super وboot اصطناعية بُنيت حسب مواصفة liblp/AOSP ولم تُجرَّب على صورة حقيقية من جهاز.

## حدود صريحة
- لم يُبنَ المشروع إلى APK ولم تُجرَّب الواجهات على جهاز في بيئة التطوير (لا Android SDK). فُحصت الصياغة وطُبّق منطق المحركات فقط.
- ext4: لا إضافة ملفات ولا حذف ولا تكبير ملف يتجاوز مساحته المخصصة. EROFS وF2FS يُكتشفان فقط (لا فك ولا تعديل). صور Sparse تحتاج تحويلاً إلى Raw قبل تعديل ext4.
- إعادة تجميع super تكتب Metadata نفسها لكل الفتحات (slots) وتبقي جدول المجموعات وجهاز الكتل كما في الأصل.
- الفلاش (fastboot) مسؤوليتك؛ التطبيق لا يكتب على أقسام الجهاز.
- تثبيت APKS/XAPK: يُفلتر حسب ABI فقط، وقد تحتاج بعض الحزم المقسّمة لملفات لا يتعرف عليها هذا الفلتر.
- ramdisk المضغوط بـ xz/bzip2/zstd/lzma لا يُفك. تعديل ramdisk في vendor_boot v4 غير مدعوم.
- الزجاج السائل محاكاة بصرية وليس انكساراً حقيقياً.

## قادم
المتصفح الداخلي، مدير تنزيل متعدد الأجزاء (16 اتصالاً)، الترمنال، عرض الشبكة والتحديد المتعدد والمشاركة، محرر Hex، المقارنة، TAR/7Z/BZIP2/XZ، وسجل العمليات.


## تغييرات الإصدار 3.0 قيد التطوير
- إزالة تسجيل الدخول إلى Google وFirebase بالكامل من واجهة التطبيق ومن اعتماديات البناء.
- لا يحتاج التطبيق إلى ملف `google-services.json` أو أسرار GitHub خاصة لتجميع نسخة Debug.
- الملف الشخصي اختياري ومحلي، ولا يوجد حساب أو مزامنة سحابية.
- نقل بيانات المحادثات والذاكرة والبرمبت من مساحة UID القديمة إلى مساحة محلية عند أول تشغيل بعد التحديث.
- الحفاظ على واجهات التطبيق والميزات الموجودة كأساس للتطوير، وإضافة الميزات الجديدة تدريجياً دون استبدال التصميم.

## بناء APK عبر GitHub Actions
كل Push إلى `main` أو `development` يشغّل بناء Debug تلقائياً. يمكن تنزيل APK من صفحة Actions بعد نجاح التشغيل.
